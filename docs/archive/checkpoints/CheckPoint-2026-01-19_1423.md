## Design Variations & Rationale

### City Page Image Architecture

**Decision:** Separate `header_image` and `city_image` fields

**Rationale:**
- Pool images showcase client products/services (header)
- Wikipedia images provide city context (showcase section)
- Both serve different purposes and should coexist
- Provides richer, more informative city pages

**Implementation:**
- `city_image`: Wikipedia showcase (unchanged)
- `header_image`: Pool image from branding.city_page_image_pool (new)
- Template displays both in distinct sections

### Path Normalization Strategy

**Decision:** Normalize at assignment time, not at template render time

**Rationale:**
- Single source of truth in config/generator layer
- Templates remain simple and focused on presentation
- Easier to test and validate
- Prevents duplicate normalization logic

3. **Relative Path Resolution:** Pages in subdirectories need careful consideration of base_path
4. **Iterative QA Critical:** Each deployment cycle revealed a new layer of the issue
