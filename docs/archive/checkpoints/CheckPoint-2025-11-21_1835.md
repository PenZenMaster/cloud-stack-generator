## Key Learnings / Design Decisions

### 1. Combined Approach Was Effective

**Decision:** Use both coverage.py and vulture together
**Rationale:**
- Coverage identifies untested code
- Vulture finds unused code
- Cross-referencing finds true dead code (0% coverage + no references)

**Result:** Successfully identified 2 truly dead modules for archival

### 2. Archival Strategy Over Deletion

**Decision:** Archive with documentation instead of deleting
**Rationale:**
- Low-risk approach
- Preserves code for potential future use
- Maintains git history with `git mv`
- Clear restoration procedures

**Result:** Successfully archived 4 files with comprehensive README guides

### 3. Moderate Cleanup Aggression

**Decision:** Conservative approach for uncertain code
**Rationale:**
- Many "unused" items are intentional API
- High false positive rate from vulture
- Better to whitelist than delete incorrectly

**Result:** Whitelist of 65+ items, avoided breaking changes

### 4. Vulture Requires Significant Manual Review

**Learning:** Vulture produces ~80% false positives
**Categories of False Positives:**
- Dataclass field definitions
- Enum constants
- UI state tracking attributes
- PyQt6 signals
- Type aliases

**Recommendation:** Use vulture primarily for finding 0% coverage files, not individual unused items

### 5. Pre-commit Hook Strategy

**Decision:** Warning-only for overall coverage (60%), blocking for cloud infra (69%)
**Rationale:**
- Maintains development momentum
- Encourages test writing without blocking progress
- Critical infrastructure requires higher standards

**Result:** Balanced approach that promotes quality without friction
